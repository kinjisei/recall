# scripts — проверки, смоуки, генераторы

## Простыми словами

Здесь всё, что проверяет приложение без человека. Чистые тесты (`test-*`)
считают логику за секунды, без сети и базы — GitHub запускает их на каждом
пуше. Проверки с базой (`check-*`) смотрят в тестовую базу. Смоуки (`smoke-*`)
открывают приложение в браузере и проходят путь, как человек: заводят
аккаунт, жмут кнопки, сверяют экран, а потом удаляют за собой аккаунт.

Всё по умолчанию смотрит в **тестовую** базу. Живую трогает только скрипт,
запущенный с `--prod`, — и такой смоук пишет в неё по-настоящему.

| Что | Где |

| секреты доставки в Vault тестовой базы на время проверки — с возвратом прежних | `_vault.mjs` (`deliverySecrets`) |

браузер; правило и почему — `checks/README.md`.

## Правила, которые нельзя нарушить

**База**

- **По умолчанию — тестовая** (`_env.mjs`, PLAN.md Ф1.2): `scriptEnv()` отдаёт
  имена приложения (`VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`,
  `SUPABASE_SECRET_KEY`…), но значения тестовой базы. Живая — только явным
  `--prod`.
- **Только новые ключи** `sb_publishable_`/`sb_secret_` (Ф1.9, `_keys.mjs`):
  старый JWT-ключ anon/service_role — отказ на старте скрипта. Старые ключи
  в обоих проектах выключаются.
- **Секретного ключа живой базы в `.env.local` нет** (решение владельца, Ф1.9).
  Смоук с `--prod`, которому он нужен (создать и удалить аккаунт на живой
  базе), откажет с подсказкой: владелец создаёт в панели временный секретный
  ключ, кладёт `SUPABASE_SECRET_KEY=…`, после прогона удаляет ключ и строку.
  Схему отсюда не поменять вовсе — токен Management API прода только читает,
  пароля базы в `.env.local` нет. `--prod` — только с согласия владельца.
- **Смоукам нужен `npm run dev:test`** (порт 5174) — отдельный от `npm run dev`
  (5173 смотрит в живую базу), чтобы смоук не завёл аккаунт на живой базе
  через интерфейс. Исключение — `smoke-offline-start`: у dev-сервера нет
  service worker'а, поэтому смоук сам собирает приложение на тестовой базе и
  поднимает `vite preview` на 4173. Сайт `recall-pgkz.vercel.app` без `--prod` скрипты не
  примут: он пускает только живую базу.
- **Новая тестовая база → `node scripts/seed-test.mjs`**, иначе регистрация
  закрыта и аккаунт не создать.
- **Аккаунт учителя удалять — `deleteTestUser` (`_users.mjs`), а не
  `deleteUser(...).catch(() => {})`.** Журнал оплат расписания только
  дописывается, а удаление аккаунта обнуляет в нём «кто отметил» — это
  правка, и удаление падает (500 без подробностей). Пустой `catch` прятал
  это: аккаунты проверок копились (нашлось 04.10.2026, Ф2.7). Помощник
  сперва удаляет строки журнала (удалять их триггер не мешает) и пишет, если
  аккаунт всё равно не удалился. Найти старый аккаунт по адресу — запросом
  к `auth.users`, а не `listUsers`: в тестовой базе их больше одной страницы.
- **Секреты доставки уведомлений в Vault — только через `_vault.mjs`**:
  он возвращает прежние после прогона. Раньше проверка удаляла их на уборке
  и выключала доставку, настроенную для живого телефона (туннель, Ф2.9) —
  пуши переставали приходить без единой ошибки.
- **Регистрация через форму — без письма.** У тестовой базы своего SMTP нет:
  встроенная почта Supabase, 2 письма в час (проверено 05.10.2026), и на
  адрес `.test` письмо всё равно не дойдёт. Смоук, который проходит форму
  регистрации, перехватывает запрос `/auth/v1/signup`: аккаунт заводит
  админка неподтверждённым, форма получает тот же ответ, что от сервера,
  почту подтверждают `updateUserById(…, { email_confirm: true })` — образец
  `smoke-teacher-path` (`signupWithoutMail`).
- **Время — от сервера, а не от своей машины.** Любую отметку времени, которую
  потом сравнивает сервер, считай от `created_at` серверной строки, а не от
  `new Date()`. Часы расходятся: в живых прогонах node отставал от базы на
  1–1,2 с, и «свежее» повторение оказывалось РАНЬШЕ выдачи домашки — сервер
  честно его не засчитывал, а проверка краснела на исправном коде. Ловушка
  сработала трижды (`smoke-homework`, `smoke-homework-ui` дважды).

**Браузер**

- **`puppeteer.launch` с Edge не работает при открытом пользовательском
  Edge** — скрипты запускают `msedge` сами и цепляются через
  `puppeteer.connect`.
- **Профиль браузера — ТОЛЬКО через `_profile.mjs`** (`profileDir('имя')`): он
  же удаляет и папку, и САМ БРАУЗЕР на выходе. Своими руками
  `--user-data-dir` не собирать: за день накопилось 74 брошенных профиля, диск
  заполнился, и три проверки подряд упали «по разным причинам» — на самом деле
  браузеру было некуда писать. Ложное падение дороже самой проверки: по нему
  чинят работающий код. Браузер запускается `detached` (иначе не к чему
  подключиться) и переживает упавший скрипт — за день так набралось два
  десятка headless-окон.
- **Снимок для владельца — `settledScreenshot(page, опции)`** (`_shots.mjs`),
  а не `page.screenshot`: экраны проявляются анимацией до ~0,8 с, и ранний
  снимок показывает бледный текст. Дождаться мало — снимок всей страницы
  (`fullPage`) сам перезапускает анимации появления. На приёмке Ф2.11б-1
  владелец так увидел «пустую» левую половину входа на компьютере. Помощник
  на время снимка обнуляет длительность анимаций и после снимка убирает
  стиль — следующие шаги смоука идут как обычно. А перед снимком ждёт
  данных (`waitForData`, до 10 с): пока в `main` есть заглушки загрузки
  (`animate-pulse`), снимок не делается — на приёмке Ф2.11 приглашение и
  «Ближайшие» на 1280 снялись серыми полосами, хотя проверка дождалась
  соседнего элемента.
- **`--headless=new` создаёт настоящее окно:** невидимое (`IsWindowVisible`
  возвращает false, поэтому в списках его не видно), но Windows показывает его
  в Alt+Tab как «Recall — английский» с пустым эскизом. Закрыть такое нельзя —
  за ним ничего нет. Пока прогон идёт, это нормально: окно уходит вместе с
  браузером. `--headless=old` не помогает (проверено). Остатки пережили всё —
  `node scripts/clean-smoke-browsers.mjs`.
- **Всем ожиданиям — `polling: 250`.** `waitForFunction` по умолчанию
  опрашивает через `requestAnimationFrame`, а в headless-вкладке кадры не
  выдаются: ожидание молча висит до таймаута. Та же причина у медиа-запросов:
  после `page.setViewport` событие `matchMedia` `change` приходит только с
  кадром, и раскладка «не переключается». Перед замером — `page.screenshot()`,
  он заставляет отрисовать кадр (`smoke-shell`, проверено: без него красное
  при верном коде).
- **`innerText` отдаёт текст УЖЕ с учётом CSS:** заголовки разделов набраны
  капсом через `text-transform`, и поиск «Все правки» их не находит —
  сравнивай без учёта регистра. Значения `placeholder` в `innerText` не
  попадают вовсе.

**Смоук и правка интерфейса**

- **Смоук переживает правку интерфейса молча.** Переименовал раздел, свернул
  аккордеон, сделал экран адресуемым — пройди `grep` по `scripts/` на старую
  подпись. Пять проверок разом оказались красными именно так: искали «Слова»
  после переименования в «Мой словарь», ждали `look after` в свёрнутой группе,
  стучались в `/teacher` без `?student=`, требовали ноль генераций там, где
  владелец решил дать две пробные.
- Новую проверку показывай красной на намеренной поломке, не коммитя её
  (правило «проверка должна уметь краснеть» — корневой `CLAUDE.md`).

## Как проверить

- `npm test` — все `test-*.mjs` разом (так же в CI).
- `npm run check` — сторожа, включая блоки описаний.
- `node scripts/smoke-features.mjs` — интерактивный обход фич (нужен
  `npm run dev:test`).
