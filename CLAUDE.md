## Что это

**Recall** — PWA для изучения английского и испанского. Переключатель EN/ES в
шапке, язык в localStorage `recall.lang`.

Два контура использования:

- **Ученик сам по себе** — слова (FSRS), чтение с разбором по тапу, речь,
  диалог с AI, грамматика, письменные работы с проверкой по критериям IELTS.
- **Студия репетитора** — преподаватель ведёт учеников: назначает материалы и
  задания, проверяет работы, видит диагностическую карту, составляет программу
  по неделям, ставит AI-квесты, печатает отчёт родителям.

Продукт продаётся репетиторам Казахстана; оплата пока ручная (Kaspi → админ
включает тариф). Начинался как личный проект владельца и его девушки —
отсюда часть решений в истории.

**Испанский контент** целиком перенесён из Flutter-приложения `d:\projects\spanish`
(оно остаётся нетронутым как источник): 46 текстов, 31 диалог, 135 фраз, весь
словарь A1–B2 (~4668 слов), 74 урока грамматики, спряжения 14 времён,
placement на 60 вопросов.

**Английский контент** авторский: 60 уроков грамматики A1–C1, 147 неправильных
глаголов, 60 фразовых (476 фраз), 911 идиом из EFE, 3591 слово «База уровня»
из 4000 Essential Words, 28 текстов A1–C1, 60 фраз речи, placement на 60 вопросов.

## Стек

- **Vite + React 19 + TypeScript + Tailwind v4** (`@tailwindcss/vite`), PWA
  (`vite-plugin-pwa`). Роутер — `react-router-dom` 7, обычный `<BrowserRouter>`
  (не data-router).
- **Supabase** — Postgres + Auth + RLS. `https://qyvkyyjqqqirmdliddsn.supabase.co`
- **AI** — через свои serverless-функции на Vercel (`api/`), ключи только на
  сервере. Модели: Gemini (цепочка flash → gemma → …) и Groq. Выбор модели
  делает СЕРВЕР по типу задачи, клиент модель не выбирает.
- **Речь** — Web Speech API для озвучки, Groq Whisper (`/api/transcribe`) для
  распознавания.
- **FSRS** — `ts-fsrs`.
- **Хостинг** — Vercel, автодеплой из `main`. Прод: https://recall-pgkz.vercel.app

Зависимостей UI — **ноль**: иконки свои (`components/icons.tsx`, инлайн-SVG в
стиле Phosphor), анимации — keyframes в `index.css`. Это осознанно: стартовый
бандл 338 КБ / gzip 105, и каждая библиотека здесь дорога.

## Механики, которые надо знать до правок

### Энергия ⚡ — единая валюта AI

Одна единица измерения на весь продукт. Любой текст про лимиты (цена разбора,
отказ сервера, тарифы, оферта) говорит про ⚡, а не про «запросы» и
«AI-действия» — иначе человек сверяет цену с числом, которого нет на экране.

- **heavy** (диалог, письмо, квесты, разбор работ) — стоит энергию;
- **light** (перевод слова, определения) и **speech** (распознавание) — стоят
  **ноль**, у них только анти-абьюз-кэп. Это чинилось отдельно: раньше тап по
  слову стоил столько же, сколько реплика в диалоге, и лимит выгорал до начала
  занятия;
- **генерации преподавателя** (материал, программа) — отдельный месячный лимит,
  не энергия.

Источник энергии: пул студии (учитель + покрытые тарифом ученики) → свой
premium → free. Суммы — в `docs/schema.sql`, функция `energy_source`.

### Тарифы

| План | ₸/мес | Что даёт |
|---|---|---|
| Free | 0 | статика без лимитов, 5 ⚡/день |
| Premium | 1990 | 30 ⚡/день |
| Репетитор Mini | 3900 | 5 учеников, пул 70 ⚡, 25 генераций/мес |
| Репетитор Start | 6500 | 10 учеников, пул 110 ⚡, 45 генераций |
| Репетитор Pro | 14990 | 30 учеников, пул 260 ⚡, 90 генераций |

Триал 14 дней всем новым. Роль преподавателя включается самим человеком
(`become_teacher`) и выключается (`stop_teaching`, если учеников нет).
Тариф покрывает первых N учеников по дате привязки — иначе можно было набрать
сотню и купить младший тариф.

### Безопасность — три правила, нарушение которых уже стоило дыр

1. **Всё, что можно подделать, считает сервер.** Балл за задание, вердикт
   перепроверки слов, прогресс квеста — security-definer RPC. Прямая запись в
   `material_assignments`, `word_checks`, `activity_log` и т.п. отозвана.
2. **RLS не прячет колонки.** У `profiles` **колоночные гранты**: новая колонка
   без явного `grant select`/`grant update` будет невидима клиенту и не
   сохранится — молча, без ошибки. Секреты (`plan`, `invite_code`, `is_admin`)
   вообще не читаются через REST, только через `get_my_plan()`.
3. **Сервер ходит в базу под токеном пользователя**, своего ключа у него нет.
   Значит любая RPC, которую зовёт сервер, доступна и из браузера. Отсюда
   `refund_token`: возврат энергии возможен только по неугадываемому номеру,
   который сервер клиенту не отдаёт.

`docs/schema.sql` заканчивается `revoke execute on all functions` —
**любая функция, добавленная после этой строки, требует своего гранта.**

### Задания собираются под ученика

В форме генерации материала есть выбор «Для кого». Если ученик выбран, в промпт
уходит сводка его диагностики (`lib/diagnosticsBrief.ts` — общая с программой
обучения): буксующие слова, слабые темы грамматики, баллы по категориям.
Без выбора материал общий, как раньше.

⚠️ Сводку пишем в ОДНОМ месте. Второй экземпляр разойдётся с первым молча, и
программа с заданиями начнут по-разному представлять одного ученика.
В заданиях работают все ТРИ типа упражнений (выбор, вписать, собрать
предложение) — фильтр `lib/materialExercises.ts` отсеивает несобираемые:
если набор слов не совпадает с ответом, упражнение невозможно пройти.
После работы ученик видит разбор с кнопкой «Почему?» (объяснение лёгкой
моделью, энергии не стоит).

Проверки: `smoke-material-diagnostics.mjs` (перехватывает запрос к AI и смотрит
промпт — не тратя ни энергии, ни генераций), `smoke-assignment-review.mjs`
(три типа упражнений доходят до ученика + разбор ошибок),
`test-material-exercises.mjs` (отсев несобираемых, в CI).

### AI: клиент шлёт задачу, а не модель

`AiTask` (9 типов) → `api/_tasks.ts` решает модель, карман квоты и требуемые
права. Раньше клиент слал `tier`, и любой мог жечь дефицитные Pro-модели.

### Навигация: адрес = «где я»

`lib/useUrlState.ts` — 12 экранов держат внутреннее состояние в query-параметрах.
Заход внутрь пушит запись в историю, возврат кареткой — заменяет. В PWA на
телефоне свайп-назад единственный способ вернуться, поэтому это не косметика.

### Дизайн — Nocturne

Единая **тёмная** тема: `class="dark"` на `<html>`, токены `--night-*` в
`index.css`, шрифт Onest локально (офлайн). Списки — `RowCard`. Печать
(`PrintSheet`) остаётся белой.

Контраст токенов пересчитан под фон `#161826`: `--night-text-25` (~3.3:1) —
**только для иконок и разделителей**, в тексте не использовать.

### Движение

Библиотек анимации нет и не планируется (разбор — `docs/motion-plan.md`).
Всё на CSS и браузерном View Transitions API; вся плавность продукта стоит
**0,8 КБ gzip**.

- Переходы между экранами — `lib/viewTransition.ts`. Включены в `useUrlState`
  (внутренние экраны) и в `components/AppLink` (между роутами и вкладками).
  Ссылки внутри приложения — **только `AppLink`**, не `<Link>`: он греет
  ленивый экран заранее и не запускает переход, пока экран не готов.
- Шапка и навигация помечены `.vt-topbar` / `.vt-nav` — так они выпадают из
  снимка и не едут вместе с содержимым.
- ⚠️ **React Router откладывает обновление через `startTransition`**, поэтому
  колбэк перехода обязан ДОЖДАТЬСЯ перерисовки (`domSettled`). Без этого
  браузер снимает два одинаковых кадра, анимация играет впустую, а экран
  меняется рывком уже после неё — и по счётчику вызовов это не видно.
- ⚠️ **Внутри `<main>` ничего не помечать `view-transition-name`**: элемент
  получает layout-containment и становится containing block для `fixed`
  потомков — шторки начнут позиционироваться от контента, а не от экрана.
- Ожидание AI — `components/Thinking.tsx` (6 мест), верный ответ —
  `.animate-answer-pop` (10 мест). Это КЛАССЫ: добавляешь новую игру или новое
  ожидание — подключай их же, иначе продукт разъедется.
- Ожидание AI — `components/Thinking.tsx`, ожидание экрана — `Loading` /
  `RowsSkeleton` из `components/Loading.tsx`, раскрывашки — `components/Reveal.tsx`
  (высоту считает CSS-грид, содержимое монтируется только пока раскрыто).
- Любая анимация — только `transform`/`opacity` и обязана попадать под
  `prefers-reduced-motion`.
- **Ничто не появляется без зарезервированного места.** Главная собирается одним
  кадром (`Promise.all` + скелетон той же раскладки); всё, что грузится позже,
  держит слот. Проверка меряет это буквально: позиция заголовка не должна
  измениться через 3,5 с.
- Проверка: `node scripts/smoke-motion.mjs`.

### Обратная связь

`components/FeedbackSheet.tsx` + `lib/feedback.ts`. Хранится событием в `events`
через `track_event` — отдельной таблицы нет намеренно: сбор работает сразу

(блок в `/admin`). Вход: меню под аватаром и «Настройки».
Проверка: `node scripts/smoke-feedback.mjs`.

## Правила работы

- Не ломать контракты из `docs/ARCHITECTURE.md`; типы — из `src/types`.
- Фича = папка в `features/*` + файл в `lib/*`. Общие файлы менять аккуратно.
- После правок — `npm run build`.
- **Нашёл ошибку — почини весь её класс.** Не одно место, а все соседние того
  же вида; общее решение выноси, в отчёте называй, сколько нашлось. Проверено
  дорого: пока правку откладывали, класс успевал вырасти.
- **Порядок деплоя:** сначала `docs/schema.sql` в Supabase, ПОТОМ push. Клиент
  зовёт RPC, которых иначе ещё нет.
- Проверка должна уметь краснеть. Тест без утверждений — не тест: у нас был
  вечно зелёный `test-fsrs-graduation.mjs` с нулём проверок и смоуки, которые
  сравнивали то, что не менялось.
- Перед `git add -A` смотреть, что попадает: бывают параллельные сессии.

## Уроки, которые дорого достались

- **Квоты Google помодельные.** Цепочка моделей складывает квоты; ставить
  дефицитную модель первой — выжечь её всем.
- **Supabase хранит email в нижнем регистре**, кириллица в локальной части
  адреса молча отклоняется (аккаунт не создаётся).
- **SQL `translate()` УДАЛЯЕТ** символы, для которых не нашлось пары в строке
  замены. Длины списков обязаны совпадать.
- **Сверка ответа продублирована**: `lib/text.ts` и `norm_typed` в SQL. Меняешь
  в одном — меняй в другом, иначе клиент покажет «верно», а балл не начислится.
  Есть парный тест `test-answermatches-sql.mjs`.
- **iOS проверяет новую версию PWA только при холодном старте** — отсюда
  `reg.update()` на `visibilitychange` в `main.tsx`.
- **Нормализация приводит начертание символа, но не удаляет символ.** Кривой
  апостроф с телефона — вина клавиатуры; пропущенный апостроф — ошибка ученика.
