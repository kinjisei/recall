# shared/ui — дизайн-система: токены, тема, общие компоненты

## Простыми словами

Весь внешний вид приложения собирается отсюда. Цвет, шрифт, размеры текста,
ширины колонок и точки перехода «телефон / планшет / компьютер» имеют
значение в одном файле — `tokens.css`. Кнопки, карточки, шторки, списки,
переключатели, раскрывашки, кнопка «назад» — общие компоненты этой папки,
построенные только на токенах. Экраны берут их, а не рисуют своё.

Зачем так строго (журнал п.22): редизайн в конце плана должен стать правкой
токенов и ~20 компонентов, а не 22 разделов. А светлая тема (п.37) работает,
только если ни один экран не красится мимо токенов: `text-white` на светлом
фоне просто исчезает.

Темы две. Тёмная (Nocturne) — по умолчанию и у всех. Светлая — черновик до
редизайна: выбрать её может только владелец и только на своём устройстве, в
админке. Для всех её включат вместе с редизайном (PLAN.md Ф5.2).

| Файл | Что там |
|---|---|
| `tokens.css` | все значения: цвета двух тем, шрифт, размеры текста, точки перехода, ширины раскладок |
| `theme.ts` | какая тема сейчас: выбор устройства → `data-theme` на `<html>`, «как в системе» следит за телефоном |
| `ThemePicker.tsx` | «Как в системе / Светлая / Тёмная» — пока только в админке (`features/admin/DeviceTheme`) |
| `breakpoints.ts` | точки перехода для JS (`DESKTOP_QUERY` → `useIsDesktop`) |
| `layouts.tsx` | общие раскладки: `CenterColumn` (упражнение, игра), `ReadingColumn` (текст + панель перевода сбоку), `ListDetail` (список + подробности) |
| `roundKeys.tsx` | клавиатура в упражнениях: `useRoundKeys` (1–4, Enter, Esc), `useRoundMode` (режим раунда + Esc — выход) |
| компоненты | `Button`, `Card` (`tone="warning" \| "danger"` — статусная карточка), `Sheet` (на компьютере — боковая панель), `Picker`, `TabPicker` (вкладки), `ChoiceGroup` (выбор значения: уровень, скорость, размер — radiogroup), `RowCard`, `Reveal`, `HowItWorks`, `Loading`/`RowsSkeleton`, `LoadError`, `Thinking`, `BackButton`/`BackHeader` (одна кнопка «назад»: `onClick` или `fallback` — назад по истории), `AppLink`, `Brand`, `Confetti`, `icons` |

Витрина всего этого — `/dev/ui` (только `npm run dev`, в сборку не попадает):
токены обеих тем, все компоненты, три раскладки, упражнение для клавиатуры.

## Компьютер (журнал п.45–46)

- **Точки перехода:** телефон < 640 ≤ планшет < 1024 ≤ компьютер. На
  компьютере каркас ставит меню слева, шторка открывается **панелью справа**
  на всю высоту (не окном по центру — правка владельца), раскладки
  раздвигаются.
- **Ширина:** экран — колонка 640 px. Раскладка с панелью (`ReadingColumn`,
  `ListDetail`) сама просит у каркаса ширину страницы до 1100 px
  (`shared/lib/screenWidth`) — экран об этом не думает. Одна такая раскладка
  на экран. Старые экраны раскладки берут при переезде (Ф3), новые (Ф2) —
  сразу.
- **Клавиатура:** 1–4 — вариант, Enter — «Проверить» / «Дальше», Esc — выход
  из раунда (решение владельца 28.09.2026). Вариант ответа помечается
  `data-key={i + 1}` — цифру рисует `index.css` псевдоэлементом и только при
  мыши/тачпаде. Не текстом: текст кнопки — это ответ, его сверяют смоуки и
  читает экранная читалка. Подключено: упражнения (`components/exercises`),
  викторины «Практики» (`QuizRunner`), тест уровня (там без Esc — 60
  вопросов жалко), Esc — все раунды «Практики» (`useRoundMode`).

## Словарь токенов

Утилиты Tailwind из `@theme` (`--color-X` → `bg-X`, `text-X`, `border-X`…):

- **поверхности:** `page` (фон страницы) · `surface` (карточки, шторки) ·
  `input` (поля) · `glass`, `step` (панели поверх авроры входа);
- **текст, от яркого к бледному:** `fg` · `fg-secondary` · `fg-tertiary` ·
  `fg-muted` (подписи) · `fg-faint` (**только иконки и разделители**, не
  текст) · `line` (рамки);
- **дымка и затемнение:** `tint` — белая в тёмной теме, тёмная в светлой;
  берётся долей: `border-tint/[0.08]`, `bg-tint/[0.04]`. `scrim` — под
  шторкой: `bg-scrim/40`, текст поверх него — `scrim-fg` (белый в обеих
  темах). `sunken` — утопленная подложка внутри карточки (переписка);
- **главная кнопка:** `primary` + `primary-fg` — в тёмной светлая заливка с
  тёмным текстом (как было), в светлой фиолетовая с белым. Только через
  `Button`, своих копий `bg-fg text-page` не заводить;
- **тени:** `shadow-card` (карточки, строки, чипы, главная кнопка) и
  `shadow-raised` («Начать занятие», меню аватара). Сама тень — переменная
  темы `--elevation-*`: **в тёмной нулевая** `0 0 #0000` (Nocturne без
  теней), в светлой — цвет текста 8 %. Нулевая, а не прозрачная: прозрачную
  тень с размытием браузер рисует, и у скруглённых углов менялось
  сглаживание — сверка скриншотов это поймала;
- **рамка управления:** `control-line`, `control-line-active` — обводка чипа
  и выбранного варианта, **только светлая** (в тёмной прозрачная: чип держит
  подложка). Берётся через `ring-1 ring-control-line` — ring не занимает
  места, рамка `border` сдвинула бы ряд чипов на 2 px;
- **герой:** `hero` → `hero-mid` → `hero-edge` (радиальный градиент карточки
  серии) и `hero-glow` (размытое пятно); `cta` → `cta-end` — подложка
  «Начать занятие». Градиентные токены — в `rgba`/hex, а не `accent` долей:
  цвет из `color-mix` браузер ведёт через oklab, и градиент расходился с
  прежним на единицу;
- **акцент:** `accent` (линии, заливка) · `accent-strong` (акцент как
  текст) · `accent-soft` + `accent-soft-fg` (мягкая подложка и текст на
  ней) · `accent-fg` (текст на заливке акцентом) · `accent-line`,
  `accent-line-soft` (рамки) · `focus` (кольцо фокуса);
- **статусы:** `danger` / `warning` / `success` — сплошной (заливка, рамка,
  точка), `-strong` (как текст на странице), `-fg` (надпись на заливке);
  мягкая подложка и рамка — долей: `bg-danger/10`, `border-danger/30`.
  Ещё четыре роли: `-soft-fg` — текст на мягкой подложке и правки «было →
  стало»; `-soft` — глубокий тон, **только долей** (`bg-danger-soft/40` —
  выбранный неверный ответ); `-surface` + `-line` — фон и рамка статусной
  карточки (`Card tone`), в тёмной равны обычной карточке;
- **текст вне шкалы Tailwind:** `text-micro` 10 · `text-caption` 11 ·
  `text-note` 13 · `text-body` 15;
- **ширины:** `max-w-column` 640 · `max-w-exercise` 576 · `max-w-reading`
  672 · `max-w-page` 1100 · `w-side` 416 · `w-list` 352.

## Правила, которые нельзя нарушить

- **Значение цвета — только в `tokens.css`.** В экранах и компонентах —
  утилиты на токенах. Сырые цвета (`text-white`, `bg-red-500`, `#fff`,
  `rgba(…)`), `[Npx]`, цвет в `style` мимо `var(--…)`, старые имена
  `--night-*`, токен через `[var(--color-…)]` и вариант `dark:` не пропускает
  сторож токенов (`scripts/checks/tokens.mjs`). Сырые значения законны только
  в `tokens.css` (и в старом `src/index.css` до его переезда).
- **Новый цвет — сразу в обеих темах.** Токен без светлого значения молча
  останется тёмным в светлой теме. Держит `scripts/test-tokens.mjs`. В
  светлом блоке задан КАЖДЫЙ токен, и ссылочные (`var(--…)`) тоже: блок
  работает и на одном элементе (ниже), а переменная, вычисленная на
  `<html>`, иначе принесла бы туда значение тёмной.
- **Светлая тема на одном блоке — `data-theme="light"`.** Так печатные листы
  (`PrintSheet`, `ReportSheet`) и «бумажный» пример отчёта на лендинге белые
  при любой теме страницы: внутри обычные токены (`bg-surface`, `text-fg`),
  а не `bg-white text-black`.
- **Тёмная не меняется от правок ради светлой.** Тень и рамка управления в
  тёмной прозрачные — это проверяет `test-tokens.mjs`; внешний вид сверяет
  `shots-compare.mjs` (обе темы, флаг `--theme light`).
- **Два класса одного свойства на элементе решает порядок в CSS, а не в
  строке.** Tailwind ставит их по алфавиту (с числами как числа): у
  `<Card className="bg-amber-950/30">` побеждал `bg-surface` карточки, и
  янтарный фон годами не показывался. Фон и рамку статуса — через
  `Card tone`, переименование цвета — со сверкой «не сменился ли
  победитель». Нужно перебить базу компонента — модификатор `!`
  (`rounded-2xl!`), как у кнопок онбординга.
- **Контраст:** текстовые токены ≥ 4,5:1, иконки и рамки ≥ 3:1 — в обеих
  темах; `fg-faint` в тексте не использовать. Держит тот же тест.
- **Тема для всех выключена** (`THEME_FOR_EVERYONE = false`): без выбора на
  устройстве — тёмная, даже если телефон светлый. Включать — только вместе с
  редизайном и нулём в стороже токенов (журнал п.37).
- **Точки перехода — пара `tokens.css` ↔ `breakpoints.ts`.** Медиа-запрос в
  CSS не читает переменные, поэтому числа записаны дважды; сверяет тест.
- **Слоя «токен на компонент» нет** (`--button-bg`…): компоненты собраны из
  утилит, лишний слой удвоил бы места правки при редизайне.
- **Тень и обводка — в общих компонентах, не на экранах.** `Card`,
  `RowCard` (сплошная), главная `Button`, `ChoiceGroup`, чип `TabPicker`
  получают их сами. Поле без рамки (`bg-input` без `border`) получает
  `ring-1 ring-control-line` — рамку, видимую только в светлой теме.
- **Одна кнопка «назад» — `BackButton`/`BackHeader`** (архитектура §3). Режима
  два: `onClick` — экран сам знает, куда (подэкран в адресе); `fallback` —
  «откуда пришёл» по истории, при прямом заходе — на `fallback` (страницы,
  куда попадают с разных мест: тарифы, оферта, Настройки, Прогресс). Своих
  круглых, текстовых «← Назад» и отдельной `SmartBack` больше нет — было пять
  вариантов.
- **Одна раскрывашка — `Reveal`** (содержимое монтируется, только пока
  открыто, разворачивается CSS-гридом). `{open && (…)}` и `<details>` для
  «показать/скрыть» не пишем: было 13 самодельных мест, все переведены.
  Заголовок-переключатель у разделов пока свой (▾/▸, стрелка, текст) — общий
  вид придёт с редизайном.
- **Иконки — `icons.tsx`, генерируются** из `handoff/icons/*.svg`
  (`node scripts/gen-icons.mjs`), руками не правятся. Иконку убрать — удалить
  её SVG и перегенерировать. 54 иконки (`IconBell` — Ф1.5); 4 неиспользуемые (`IconStudents`,
  `IconSpeech`, `IconSpeechFill`, `IconMicFill`) удалены 28.09.2026.

## Как проверить

- `node scripts/smoke-ui.mjs [--shots <папка>]` — тема за флагом, шторка на
  390 и 1280, три раскладки на 390 и 1280, клавиатура на витрине и в
  настоящем раунде «Практики» (нужен `npm run dev:test`).
- `node scripts/test-tokens.mjs` — полнота и контраст обеих тем (в CI).
- `node scripts/test-checks.mjs` — сторож токенов на примерах (в CI).
- `node scripts/shots-compare.mjs --save <папка>` до и после правки, затем
  `--compare <до> <после> --out <разница>` — сверка по пикселям (нужен
  `npm run dev:test`). Шум между двумя прогонами одного кода: «слово дня»,
  код-приглашение, адрес тестового аккаунта.

## Решения и почему

- Старые имена `--night-*` переименованы механически за один коммит
  (решение владельца 28.09.2026): два способа писать один цвет новые экраны
  переписывали бы у соседних файлов.
- Выбор темы хранится на устройстве, не в профиле: одно устройство может быть
  светлым, другое — тёмным.
- Тема ставится из `app/main.tsx` до первого рендера. Короткая вспышка
  тёмного фона до запуска скрипта у светлой темы остаётся: блокирующий
  скрипт в `<head>` стоил бы запроса на старте всем ради одного владельца
  (CSP запрещает встроенный). Решается при включении темы для всех (Ф5.2).
