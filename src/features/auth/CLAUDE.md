# auth — вход, восстановление и смена пароля

## Простыми словами

Вход (`/login`), «Забыли пароль?» (`/forgot`) и новый пароль по ссылке из
письма (`/reset-password`) — открываются без входа. Смена пароля для
вошедшего — блок «Безопасность» в Настройках.

Забыл пароль — просишь письмо. В письме и ссылка, и восьмизначный код, оба
живут 30 минут: можно нажать ссылку или ввести код. Чужому мы не говорим, есть
ли такой аккаунт: ответ одинаковый для любого адреса. Нет доступа к почте —
восстановить нельзя намеренно: только написать нам, адрес меняется руками в
панели Supabase. Кнопки «сбросить пароль ученику» нет ни у преподавателя, ни у
владельца — это была бы кнопка «забрать аккаунт».

Письмо собирает Supabase, а не мы. **Пока шаблон в панели не заменён, письмо
уходит стандартное английское, без кода и с чужой ссылкой** — как заменить:
`docs/supabase-auth-setup.md`.

| Файл | Что там |
|---|---|
| `LoginPage.tsx`, `authUi.tsx` | вход и регистрация, общий вид экранов входа |
| `ForgotPasswordPage.tsx`, `ResetPasswordPage.tsx` | попросить письмо; новый пароль по ссылке или коду |
| `src/features/settings/SecuritySection.tsx` | смена пароля в Настройках |
| `src/lib/passwordReset.ts` | одно место на все три экрана восстановления и смены |

## Правила, которые нельзя нарушить

- **`lib/passwordReset.ts` — одно место на три экрана:** `/forgot`,
  `/reset-password`, «Безопасность» в Настройках.
- **В письме и ссылка, и код** (у нашего проекта код восьмизначный), живут
  30 минут; экран принимает оба пути.
- **Токен проверяется при отправке формы, а НЕ при открытии страницы.** Ссылки
  в письмах открывают антивирусы и превью мессенджеров; проверка на входе
  сжигала бы одноразовый токен до человека. `token_hash` вычищается из адреса
  сразу — иначе живёт в истории и уезжает в `Referer`.
- **После смены пароля — `signOut({ scope: 'others' })`.** Пароль меняют
  потому, что в аккаунт зашли; чужой refresh-токен продлевается сам. Supabase
  обрывает чужие сессии и сам, но `others` (а не `global`) — наше решение:
  человек остаётся вошедшим там, где менял.
- **Смена пароля в Настройках спрашивает текущий.** Supabase его не требует:
  без проверки чужой открытый ноутбук = потерянный аккаунт.
- **Существование аккаунта не раскрываем:** ответ один и тот же для любого
  адреса. Регистрация занятого адреса тоже не раскрывает (Supabase отдаёт успех
  с пустым `identities`) — проверено на проекте.
- **Без доступа к почте восстановления нет** — строчка «Напишите нам»
  (`shared/lib/contacts.ts`), адрес меняется руками в панели.
- **`/reset-password` обязан быть в списке Redirect URLs** панели Supabase —
  туда ведёт ссылка из письма (`app/routes.ts`).

## Как проверить

Обе проверки — без единого письма.

- `node scripts/smoke-password-reset.mjs` — весь путь; запрос перехватывается
  в браузере, ссылка и код берутся через `admin.generateLink()`. Прод — тем же
  прогоном: `AUDIT_BASE_URL=https://recall-pgkz.vercel.app node
  scripts/smoke-password-reset.mjs --prod` (создаёт и удаляет аккаунт на
  живой базе — только с согласия владельца).
- `node scripts/check-auth-setup.mjs` — настройки панели: белый список адресов
  возврата и Site URL. Их правят руками, без истории и ревью, а код о них не
  знает и остаётся зелёным при любой их поломке.

## Решения и почему

- Шаблон письма, Redirect URLs и срок жизни кода — в панели Supabase,
  инструкция — `docs/supabase-auth-setup.md`.

  возврата отклоняется, код восьмизначный, смоук на проде 34/34.
