# Опись: ядро ученика (обучение)

> Часть 2 механической карты `docs/architecture/code-map.md`. Область:
> `features/words`, `flashcards`, `practice`, `grammar`, `reader`, `study` +
> связанные `lib/*`. Цель — вход в решение «язык как настройка», материал для
> нарезки при Strangler Fig переезде. Ссылки — `путь:строка`.

---

## 1. Разделы features/

### 1.1 `features/words/` — мини-игры (9 файлов, 2089 строк)

Одиночные игры на карточках пользователя + словах паков: «Значения» (Match),
«Пропуск/Перевод/Аудирование» (`QuizModes.tsx`, общий `QuizRunner`), «Спринт»,
«Диктант», «Собери фразу», плюс `MyWords.tsx` (466, список+редактор+карточка
слова в одном файле) и `AddCardForm.tsx`. Вызываются из `practice/PracticePage`.

Данные: `wordPool.loadGamePool()` (карточки + добор паками), `data/english|
spanish/index.ts` для фраз в `SentenceBuilder`. Пишут `cards`, `review_states`
(`markWrong`→`fsrs.reviewCard`), `activity_log`, localStorage
(`game_misses`, `recent_words`). Загрузка — свой `useEffect`+`alive`-флаг в
каждой игре, общих хуков кроме `GameShell` нет.

**Разнобой:**
- `SentenceBuilder.tsx:13` статически импортирует `../../data/spanish`
  (eager-индекс) ради одного `spanishSentences` — тянет заодно
  `readings.json` (190 КБ) + `dialogues.json` (70 КБ). Английский индекс
  такого не делает — асимметрия в пользу английского. Тот же паттерн вне
  области — `PronunciationPage.tsx:25`.
- `MyWords.tsx` — 466 строк в одном файле.
- `QuizModes`/`SprintMode` не используют `lib/selfCorrect` (один клик, без
  второй попытки) — осознанное разделение «игры vs упражнения», но нигде не
  зафиксировано явно как правило.

**Развилки по языку (5):** `MatchMode` (EN — определения через
`lib/definitions`, ES — перевод — продуктовое решение, не косметика),
`SentenceBuilder`/`AddCardForm` (поле/подпись), `WordSheet.tsx:196` (EN — IPA/
аудио Free Dictionary, ES — только TTS). Сводимы к данным, кроме пары
«EN-определения vs ES-перевод» и источника произношения.

**Инварианты:** балл по первой попытке — `selfCorrect` (только в
`DictationMode`/`SentenceBuilder`); игры штрафуют, не поощряют FSRS
(`gameUtils.ts:39-64`, порог 3 промаха/7 дней — `gameMisses.ts`); обманки —
единое правило похожести (`distractors.ts`).

**Проверки:** `test-distractors.mjs`, `test-wordpool.mjs`,
`test-fsrs-graduation.mjs` — в CI. Живых смоуков по играм нет.

**Резать:** каждая игра — независимый модуль на общем `GameShell`/`wordPool`;
переносить по одной. `MyWords`/`AddCardForm` логически ближе к «словарю»
(Учёба), чем к играм.

### 1.2 `features/flashcards/` — FSRS-повторение (4 файла, 884 строки)

Экран «Повторение»: карточка на весь экран, свайп/кнопки, встроенная
перепроверка от преподавателя, шторка паков. Файлы: `DeckReview.tsx` (292),
`SwipeCard.tsx` (212), `WordCheckRunner.tsx` (182), `PacksSheet.tsx` (194).

Данные: `fsrs.getDueCards/reviewCard`, `wordChecks` (`word_checks` + RPC
`submit_word_check`), `wordPacks.loadPacks`. `DeckReview` держит очередь в
state, `alive`-ref против гонки при смене языка, `swiping`/`handledKey` —
защита от двойного свайпа.

**Разнобой:** `PacksSheet.tsx:150` — раскрывашка сырыми `▾`/`▸`, тогда как
`GrammarPage.tsx:264-265` для той же роли использует `IconCaretDown`/
`IconArrowRight`. `PacksSheet` и `wordPool.loadPackItems` независимо парсят
EN/ES-поля пака (см. §2.2) — дублирование маппинга.

**Развилки (1):** подпись «испанских/английских слов» в `PacksSheet`. Данные
и структура полностью общие через `wordPacks.ts`.

**Инварианты:** перепроверка НЕ получает вторую попытку (`WordCheckRunner` —
сразу правильный ответ после первого ввода); `answerMatches`, а не голое
сравнение (`WordCheckRunner.tsx:40,52`); «не знаю» возвращает карточку в конец
ТЕКУЩЕЙ очереди (`DeckReview.tsx:129-131`); верный ответ на повторении снимает
штраф игр — `clearMisses` (`DeckReview.tsx:124`).

**Проверки:** нет чистых тестов раздела; живые `smoke-wordcheck.mjs`,
`smoke-markwords.mjs`, `smoke-basepacks.mjs` — не в CI.

**Резать:** `DeckReview`+`SwipeCard` не зависят от языка вообще, переносятся
как есть. `PacksSheet`/`WordCheckRunner` — в модуль «словарь ученика».

### 1.3 `features/practice/` — хаб тренировок (2 файла, 630 строк)

Вкладка «Практика»: один раскрытый раздел из четырёх + три свёрнутых, счётчик
«к повторению», ведомая сессия. `PracticePage.tsx` (439 — на пороге правила
300 строк), `GrammarMixMode.tsx` (191).

Режим и раскрытая группа — в URL (`?m=`, `?g=`), последняя группа — в
`localStorage.recall.practice_group` (не в БД).

**Разнобой:** `GrammarMixMode.tsx:85-86` дословно дублирует ветку выбора
модуля грамматики из `GrammarPage.tsx:192-194` (`lang==='es' ? import(...) :
import(...)`) — тот же код в двух файлах.

**Развилки (2):** какой JSON грузить (дубль выше), подпись плитки «Глаголы»
(«Спряжения»/«Неправильные» — отражает реальную разницу контента).

**Инварианты:** ведомая сессия — автоперехват `flashcards` ровно один раз
(`PracticePage.tsx:228-242`, тот же контракт `guided.ts`, что в `StudyPage`);
счётчик «к повторению» — `countDueCards`, а не длина `getDueCards(50)`, чтобы
не разъезжаться с Главной.

**Проверки:** отдельных тестов раздела нет; логика упражнений покрыта
`test-material-exercises.mjs`.

**Резать:** хаб — тонкая оболочка-оркестратор. `GrammarMixMode` стоит
объединить с `GrammarPage`'s `LessonsSection` вокруг одного загрузчика тем.

### 1.4 `features/grammar/` — уроки и глаголы (4 файла, 1847 строк)

Уроки по уровням (теория→упражнения) на общем типе для обоих языков; раздел
«Глаголы»: ES — спряжения (справочник+тренажёр 110 упр.), EN — неправильные
(147) и фразовые (60/476). Файлы: `GrammarPage.tsx` (643 — самый большой файл
области: 5 экранов в одном компоненте), `ConjugationSection.tsx` (477, ES-only),
`IrregularVerbsSection.tsx` (394, EN-only), `PhrasalVerbsSection.tsx` (333,
EN-only).

Данные: `data/english|spanish/grammar` (общий тип `GrammarTopic`),
`data/spanish/conjugation`, `data/english/irregular`, `data/english/phrasal`.
Пишет `grammar_mistakes` (`lib/mistakes`, синк с localStorage) и отдельно
`recall.verb_mistakes.*` (только localStorage, `lib/verbMistakes`).

**Разнобой (главная находка раздела):** банк ошибок раздваивается по
назначению незаметно. Уроки грамматики синкают ошибку на сервер
(`grammar_mistakes` → видно преподавателю в диагностике). Тренажёры глаголов
— **только localStorage**, преподаватель их не видит. `PhrasalVerbsSection`
вообще не ведёт банк ошибок — ни локально, ни на сервере. Три похожих
тренажёра — три разных уровня учёта ошибок, нигде не описано как решение.
Плюс: `GrammarPage.tsx` 643 строки в одном файле; дубль загрузки тем в
`GrammarMixMode` (см. §1.3).

**Развилки (3):** выбор JSON, подпись уровней («A1–B2» ES / полный список EN),
ветка «Глаголы» (`ConjugationSection` vs `EnglishVerbs`). Уроки унифицированы
типом `GrammarTopic` — общий код. «Глаголы» НЕ сводимы к данным: спряжения ≠
таблица форм ≠ фразовые глаголы — либо три модуля, либо общая абстракция
«тренажёр форм слова» (её сейчас нет).

**Инварианты:** `shouldReveal`/`selfCorrect` — общий `ExerciseView`
(`components/exercises.tsx`) для уроков и `GrammarMixMode`; балл по первой
попытке; «Мои ошибки» — снимок банка на момент открытия экрана
(`GrammarPage.tsx:574`); `answerMatches`/`correctAnswerText` из `lib/text.ts`.

**Проверки:** `test-material-exercises.mjs`, `validate-exercises.mjs` — в CI
(структура JSON: mcq/fill/order, дубли вариантов). Нет теста на банк ошибок
или навигацию `GrammarPage`.

**Резать:** уроки — один модуль без изменений. Три «глагольных» тренажёра —
отдельные модули по общему шаблону (справочник+тренажёр+банк ошибок),
которого сейчас нет как абстракции — стоит создать, заодно закрыв дыру с
`PhrasalVerbsSection` и несинкающимся `verbMistakes`.

### 1.5 `features/reader/` — чтение (4 файла, 819 строк + данные)

EN: 28 встроенных текстов A1–C1, перевод по тапу на слово. ES: отдельный
экран, тексты (46) + диалоги (31), перевод по абзацам/репликам кнопкой. «Мои
тексты» (вставка/PDF/DOCX/TXT) — общий блок. Файлы: `ReaderPage.tsx` (181,
маршрутизатор EN/ES), `SpanishReader.tsx` (253, ленивый чанк), `MyTextsBlock.tsx`
(195), `sampleTexts.ts` (190 — **английские тексты как TS-код в `features/`,
не в `src/data/`**).

Данные: EN — `sampleTexts.ts` (жёсткий массив, только текст); ES —
`data/spanish/readings.json`+`dialogues.json` (перевод по абзацу заложен в
структуру). «Мои тексты» — `lib/myTexts.ts`, localStorage only, лимит 15 000
знаков/10 текстов.

**Разнобой (главная находка раздела):** английская и испанская читалка — два
разных ПО УСТРОЙСТВУ экрана, не один компонент с ветками по данным. EN: один
список по уровню, перевод только на слово. ES: таб «Тексты/Диалоги», перевод
абзаца/реплики целиком кнопкой, озвучка реплики. Это разный набор функций, не
разные поля одних данных — свести к «языку как настройке» здесь значит сперва
решить продуктовый вопрос (добавить абзацный перевод в EN? убрать из ES?), а
не просто унифицировать типы. Плюс: EN-тексты лежат вне `src/data/`, нарушая
собственное правило проекта; `SentenceBuilder`/`PronunciationPage` эагерно
тянут `data/spanish/index.ts` целиком, хотя `SpanishReaderPage` сам —
образец правильного ленивого паттерна (`ReaderPage.tsx:13-15`).

**Развилки (2):** `MyTextsBlock`, выбор `EnglishReaderPage`/`SpanishReaderPage`
в `ReaderPage.tsx` — по факту не развилка, а выбор другого компонента,
крупнейшая точка ветвления по языку в области.

**Инварианты:** тап по слову → `WordSheet`→«в колоду» одинаково в EN/ES;
`GuidedNext step="reader"`; «Мои тексты» намеренно не синкаются (чужой
копирайт — `myTexts.ts:1-8`).

**Проверки:** нет чистых тестов; `extractFileText` не покрыт автотестами.

**Резать:** самая рискованная часть переезда — два экрана на одну роль.
Сначала решить, входят ли абзацный перевод/диалоги в новый EN-контент, иначе
унификация типов закрепит нынешнюю асимметрию как окончательный дизайн.

`StudyPage.tsx` — 555 строк, хаб и подэкран «Слова» (`WordsStudy`) в одном
файле. Баннер частичного отказа сети есть только здесь, на аналогичном

**Развилки (6):** описание уровней чтения/грамматики, выбор `esLevel`/
`enLevel`, число вопросов плейсмента (40 ES / 50 EN — реальное различие теста).

**Инварианты:** ведомая сессия → авто-открытие `reader` ровно один раз
(`StudyPage.tsx:67-73`); «хотя бы один источник не ответил», а не «упали все»
(находка ревью, `StudyPage.tsx:221-226`); домашка — одна строка вместо трёх.

**Проверки:** нет чистых тестов; `smoke-self-material.mjs` — не в CI.

**Резать:** `StudyPage` — тонкий оркестратор, переносится после разделов, на
которые ссылается. `SelfMaterialPage` независим (заодно поправить баг с
уровнем).

## 2. Модули lib/ — учебное ядро

### 2.1 Хранилище и повторение (язык-нейтральные)

`cards.ts` (213, CRUD карточек/колод), `fsrs.ts` (223, обёртка `ts-fsrs`:
`getDueCards`/`countDueCards`/`reviewCard`), `wordChecks.ts` (188,
перепроверка). Ни один не содержит веток по языку — `lang: AppLang` везде
параметр фильтрации колод по колонке БД, а не условие в коде. Готовый образец
«язык как данные» для ориентира при переносе остального.

Инвариант: `countDueCards` — единственная точка правды для счётчика и на
Главной, и в «Практике» (`fsrs.ts:147-159`, зафиксированная находка ревью 2А).
Проверка: `test-fsrs-graduation.mjs` (в CI) — промах в игре не должен
обнулять зрелое слово.

### 2.2 Пул слов для игр

`wordPool.ts` (311, `loadGamePool` — карточки + добор паками по близости
CEFR), `pickRound.ts` (79, приоритет свежих слов, `DECK_SHARE=0.6`),
`distractors.ts` (94, обманки по теме/уровню/части речи/длине, `ruPos` —
эвристика по русскому переводу, не зависит от языка карточки),
`recentWords.ts` (38, анти-повтор, localStorage 40 записей/язык),
`gameMisses.ts` (61, 3 промаха/7 дней → серьёзно).

**Разнобой:** маппинг полей пака (`english`/`example_en` vs `spanish`/
`example_es`) продублирован в трёх местах — `wordPool.ts:170-185`,
`wordPacks.ts:166-185`, косвенно `SentenceBuilder.tsx:53-56`. Три копии одного
переключателя вместо одной нормализующей функции.

Проверки: `test-wordpool.mjs`, `test-distractors.mjs` — в CI, чистые (без
импортов — специально ради запуска голым Node, см. `recentWords.ts:8-9`,
`pickRound.ts:10-13`).

### 2.3 `wordPacks.ts` (192) — сборка паков

Единственная точка склейки одноимённых тем, дедупа слов (`front` без
регистра/пробелов) и резки тем >30 слов на части по 20 (хвост <8 приклеивается
к предыдущей). Общая для ученика (`PacksSheet`) и выдачи преподавателем.
Полностью язык-нейтральна — принимает уже нормализованный
`PackWord{front,back,example}`, разница EN/ES снаружи, в `loadPacks()` (см.
дублирование выше). id частей не сохраняются нигде — алгоритм резки можно
менять без миграций. Проверка: `test-word-packs.mjs` (в CI, сверяет СОСТАВ
пака, не количество).

### 2.4 Самокоррекция и сравнение ответов

`selfCorrect.ts` (109) — «сначала где ошибка, ответ потом», единое для всех
печатных упражнений; `text.ts` (99) — `normalizeAnswer`/`answerMatches`,
дублируется на сервере (`norm_typed`, вне области). Оба язык-нейтральны —
работают со строками, не зная про `AppLang`. Проверка: `test-material-
exercises.mjs` (в CI, включает «подсказка не выдаёт ответ»).

### 2.5 Банки ошибок

`mistakes.ts` (85, синк в БД `grammar_mistakes`, ссылка `{topicId, ex}`) vs
`verbMistakes.ts` (30, только localStorage, ссылка — голый `string id`). См.
разнобой §1.4 — одна и та же функция «отложить на переигровку», два разных
формата и уровня персистентности.

### 2.6 Определения/словарь

`definitions.ts` (234, режим «Значения» EN: Gemini light → Free Dictionary
резервом), `dictionary.ts` (84, обёртка Free Dictionary — **жёстко английский
эндпоинт**, `dictionary.ts:43`, испанского аналога физически нет в проекте),
`contextDict.ts` (84, перевод в контексте через Gemini — единственный из
троих действительно язык-нейтральный, промпт зависит от `lang` только
текстом). Развилка тут принципиальная, не сводится к настройке: у испанского
нет альтернативного источника произношения кроме браузерного TTS. Перенос
должен явно завести понятие «источник произношения по языку» — сейчас оно
неявно зашито в `WordSheet.tsx:196` и `MatchMode.tsx:94-104`.

### 2.7 Уровень ученика

`level.ts` (24) — фасад `getUserLevel(lang)`: ES → `esLevel.getEsLevel()`
(localStorage, синхронно), EN → `profile.getProfile().level` (БД, асинхронно,
через кэш). `esLevel.ts` (52) — write-through: пишет в localStorage сразу,
асинхронно шлёт в `profiles.es_level`; `hydrateEsLevel` сводит источники при
загрузке профиля (сервер выигрывает только если локально пусто). Не баг, а
исторический шов: свойства паритетны (оба переживают смену устройства), но
МЕХАНИЗМ разный — новый код, читающий уровень напрямую вместо `level.ts`,
рискует завести третий способ (уже случилось в `SelfMaterialPage.tsx:39`).

### 2.8 Прочие язык-нейтральные утилиты

`guided.ts` (161) — ведомая сессия целиком в `sessionStorage`, без языка;
инвариант «автоперехват ровно один раз» — отметка ставится в момент
навигации, не в теле эффекта (историческая ловушка StrictMode,
`guided.ts:14-28`). `activity.ts` (223) — стрик и `activity_log`, один стрик
на пользователя, без разделения по языку. `random.ts` (20) — чистый
shuffle/sample. `morph.ts` (49) — ⚠️ вопреки названию не про словоформы: это
View Transitions («плитка выросла в экран», `markMorph`/`useMorphName`),
используется в `GameShell`/`PracticePage`. `myTexts.ts` (100), `settings.ts`
(58) — localStorage-хранилища, язык только ключ.

## 3. Форма данных: EN vs ES

| Сущность | EN | ES | Различие формы |
|---|---|---|---|
| Слова пака | `EnglishWord{english, russian, example_en, level, topic_id}` | `SpanishWord{spanish, russian, example_es, example_ru, level, topic_id, frequency_rank}` | Разные имена терма/примера; у ES есть `example_ru`/`frequency_rank`. Три места в коде вручную мапят оба варианта (§2.2). |
| Тексты | `sampleTexts.ts` — TS-массив `{id,level,title,body}`, код, не данные, без перевода | `readings.json` → `{id,title,titleRu,level,paragraphs:[{es,ru}]}`, JSON, перевод абзаца — часть структуры | EN физически нечем показать абзацный перевод без новых данных. |
| Диалоги | Отсутствуют как класс | `dialogues.json` → `{id,title,level,lines:[{speaker,es,ru}]}` | Целая категория контента есть только у одного языка. |
| Фразы речи | `EnglishSentence{id,level,en,ru}`, отдельный лёгкий модуль | `SpanishSentence{id,level,es,ru}`, в общем файле с readings+dialogues | Одна форма записи, разный вес окружения (см. §1.1). |
| Грамматика | `GrammarTopic` (общий тип) | `GrammarTopic` (тот же тип) | Единственная категория, где форма буквально совпадает. |
| Глаголы | `irregular.ts` + `phrasal.json` — два формата, специфичных для EN | `conjugation.ts`+`conjugation_reference.json` — формат спряжений | Разная природа категории — не сводится к общей форме без потери смысла. |
| Идиомы | `words_idioms.json` (911) — как обычные `EnglishWord` | Нет отдельной категории, размазаны по `words_phrases_dialogues*.json` | Формально та же таблица, разный охват контента. |

**Вывод.** Слова и грамматика унифицируемы через общий загрузчик
(`wordPacks.ts`, тип `GrammarTopic`) — почти сделано. Тексты/диалоги/глаголы —
структурно разные категории по языку: «язык как настройка» здесь означает не
смену данных под одним экраном, а решение, какие категории контента должны
появиться (или исчезнуть) у противоположного языка, прежде чем экраны можно
объединить.

## 4. Сквозные наблюдения по области

1. Язык почти нигде не определяет ПРАВИЛА — только какой файл читать и какую
   подпись показать. Содержательные исключения: источник произношения (EN —
   Free Dictionary, ES — только TTS), режим «Значения» (EN — определения, ES
   — перевод), набор категорий контента (диалоги/абзацный перевод только у ES).
2. Три независимые копии одного маппинга EN/ES-полей слова (`wordPool.ts`,
   `wordPacks.ts`, `SentenceBuilder.tsx`) — кандидат на единую нормализующую
   функцию, а не три раза чинить один и тот же баг.
3. Банки ошибок разошлись по назначению незаметно: у грамматики есть синк на
   сервер, у тренажёров глаголов — только у двух из трёх и только локально, у
   фразовых глаголов банка нет вообще. Не описано нигде как решение.
4. Правило выбора JSON грамматики по языку продублировано буквально
   (`GrammarPage.tsx`, `GrammarMixMode.tsx`).
5. Читалка — единственное место, где ветка по языку меняет весь UX, а не
   только данные; главный риск закрепить асимметрию как окончательный дизайн
   вместо осознанного решения.
6. Файлы-хабы и «микс»-режимы стабильно перерастают 300 строк
   (`GrammarPage.tsx` 643, `StudyPage.tsx` 555, `MyWords.tsx` 466,
   `PracticePage.tsx` 439) — экран объединяет список+деталь+под-режим в одном
   файле без вынесения подэкранов.
7. Уровень читается синхронно для ES и асинхронно для EN — новый код обязан
   знать `lib/level.ts` как фасад, иначе плодится третий способ (уже
   случилось в `SelfMaterialPage.tsx:39`).
8. Игры (одна попытка, прямой reveal) и упражнения (`selfCorrect`, вторая
   попытка) — два разных, но нигде явно не задокументированных как правило,
   контракта; держится на последовательном именовании, не на коде.
9. Утилиты `random`/`pickRound`/`distractors`/`recentWords` написаны БЕЗ
   импортов специально, ради запуска чистым Node в CI — ограничение стоит
   сохранить при переносе.
10. Все чистые lib-тесты области в CI (`test-distractors`, `test-wordpool`,
    `test-fsrs-graduation`, `test-material-exercises`, `test-word-packs`,
    `validate-exercises`), но ни один UI-компонент раздела не покрыт живым
    смоуком в CI.
