# Облачная сессия Claude Code — правила

> Для сессий на claude.ai/code. Общие правила — `CLAUDE.md` в корне; здесь —
> только то, чем облако отличается от работы в VS Code владельца.

## Чего в облаке нет — и не ищи

- `.env.local`: ключей Supabase, `TEST_GEMINI_API_KEY`, Groq — нет.
- Тестовой и живой базы: `npm run dev:test`, `db:migrate`, `check-*` на
  тестовой базе, смоуки — не запускаются.
- Gemini: `check-ai-*` не запускай — ключа нет, а квота тестового ключа
  общая (20 запросов в сутки на модель) и нужна для прогонов владельца.
- Файлов вне git: `scripts/ai-quality/runs/`, `scripts/ai-quality/official/*.json`.
- Браузера для снимков и смоуков.

Что требует этого — не обходи и не выдумывай замену: запиши в отчёт
строкой «Проверить локально: …» (какой скрипт, с какими флагами, что
должно получиться).

## Ветка

- Начни с `git fetch origin` и создай свою ветку от `origin/cloud/f220-base`
  (если в задании не сказано другое).
- Пушь только в свою ветку. В `main` и в `cloud/f220-base` — никогда.
  Правило `CLAUDE.md` «коммит без пуша» в облаке звучит так: пуш — только в
  свою ветку, иначе работа не дойдёт до владельца.
- Открой pull request в `cloud/f220-base`, но не сливай его. Сливает Claude
  локально — после смоуков на тестовой базе.

## Перед каждым коммитом

```
npm ci            # один раз в начале
npm run build
npm run check
npm test
```

Все три зелёные. Описание модуля (`CLAUDE.md` его папки) — правь в том же
коммите. `--no-verify` нельзя. Проверка, которую ты написал, обязана
краснеть на испорченном коде — проверь это и напиши в отчёте, как.

## Чего не трогать

- `docs/PLAN.md` — параллельно работают несколько чатов; статус пишется при
  слиянии.
- Файлы вне своей задачи (в задании сказано, какие твои). Нашёл ошибку в
  чужих — опиши в отчёте, не чини.
- Промпты AI и пороги — только если это прямо задача.

## Отчёт — в описании pull request, по-русски, простыми словами

1. Что сделано и зачем (2–5 строк).
2. Какие файлы изменены.
3. Проверки: build / check / test — результат; как проверка краснеет.
4. «Проверить локально: …» — всё, что облако проверить не смогло.
5. Вопросы владельцу, если есть — с плюсами и минусами вариантов.
