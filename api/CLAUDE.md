# api — сервер: AI, распознавание речи, доставка уведомлений

## Простыми словами

Наш сервер — несколько функций на Vercel: `/api/gemini` (все задачи AI:
перевод слова, Диалог, разбор письма, материалы…), `/api/transcribe`
(распознавание речи) и `/api/notify` (доставка уведомлений, её будит база).
Ключи AI живут только здесь — браузер их не видит.

Браузер присылает не модель, а задачу: «перевести слово», «ответить в
Диалоге». Сервер сам решает, какую модель спросить, проверяет вход и права,
списывает ⚡ и возвращает её, если ответа не было. Модели идут цепочкой: одна
не ответила (лимит, сбой, зависла) — спрашиваем следующую. У каждого запроса
наружу есть срок: 27.09.2026 поставщик AI завис, функция ждала до обрыва
Vercel (504), запасные модели остались не спрошены, а ⚡ ученика не вернулась.

Модели — цепочки Gemini по уровню задачи (`_core.ts`) и Groq
(`openai/gpt-oss-*`: первая модель для перевода слова и последний рубеж
обычных задач). Речь — Groq Whisper. Учёт расхода и лимиты моделей —
`src/domains/ai/CLAUDE.md`; правила энергии — `features/billing/CLAUDE.md`.

| Файл | Что там |
|---|---|
| `gemini.ts`, `transcribe.ts`, `notify.ts` | функции Vercel (`maxDuration` 60 / 30 с; `notify` — вход по секрету, `src/domains/notifications/CLAUDE.md`) |
| `_tasks.ts` | карта «задача → модель, карман квоты, требуемые права» |
| `_core.ts`, `_geminiBody.ts`, `_groq.ts`, `_stt.ts` | вызовы Gemini (обычный и поток), Groq, Whisper |
| `_auth.ts` | вход, проверка роли, списание и возврат ⚡ (`spend_energy`, `refund_ai_call`) |
| `_timeouts.ts` | все сроки ожидания и запрос со сроком (`timedFetch`, `openStream`) |
| `_usage.ts` | журнал вызовов AI (`log_ai_call`) |
| `_channels.ts` | каналы доставки уведомлений (пока пусто: push — Ф2.9, Telegram — Ф4.3) |

Файл с `_` в начале Vercel не превращает в отдельную функцию.

## Правила, которые нельзя нарушить

**Клиент шлёт задачу, а не модель**

- `AiTask` (11 типов) → `_tasks.ts` решает модель, карман квоты и требуемые
  права. Раньше клиент слал `tier`, и любой мог жечь дефицитные Pro-модели;
  запрос без `task` (старый путь `tier`/`provider`) с Ф1.6 — 400.
- Тип `AiTask` и карта совпадают в обе стороны, и каждую задачу шлёт хотя бы
  один экран — `test-aitasks.mjs` (мёртвая задача `batch` жила в карте с
  июля).
- **Нет функции списания — AI закрыт** (503), а не открыт по одной
  валидности токена. Прежний «пропуск, пока миграция не залита» с порядком
  «миграция, потом код» стал бы безлимитным AI при первой же поломке.

**У каждого запроса наружу есть срок**

- **Голый `fetch(` в `api/` запрещён** — только через `_timeouts.ts`
  (`timedFetch`, `openStream`). Новый запрос без срока сделает `npm test`
  красным.
- **Зависшая модель = отказ, как 429:** цепочка идёт к следующей. Сбой связи —
  то же самое.
- **Бюджет минуты** (`gemini.ts`, `maxDuration` 60): работа кончается к
  52-й секунде (запас 3 + итог с возвратом 5), цепочка Gemini — к 40-й, чтобы
  Groq-у остались его 12 с. У `transcribe.ts` (30 с) Whisper кончается к
  22-й. Окно одной модели: lite 8 с, standard 25, max 35; поток — 15 с до
  первых слов, 10 с тишины между кусками. Числа — оценки без замеров; замеры с
  Ф1.6 копятся в журнале (`/admin` → «Расход AI»: среднее, 95 %, первые
  слова) — набрались, сверить.
- **Оборванный поток сервер рвёт (`res.destroy()`), а не закрывает.** Статус
  200 к тому моменту ушёл, и «чистый» конец клиент принял бы обрывок за целую
  реплику. `chatStream` на обрыве бросает ошибку — экран Диалога вернёт текст
  в поле ввода.
- **Supabase не ответил — это 503 «недоступен»**, а не «требуется вход» и не
  «только преподавателю» (`UNAVAILABLE` в `_auth.ts`). Не ответило само
  списание — возврат по тому же номеру: списание могло пройти.
- **Сроки — параметр** (`handle(req, res, сроки)`): тест гоняет все пути за
  секунды.

**Модели выключают без нашего ведома**

- 16.08.2026 Groq выключил обе наши Llama, и полтора месяца цепочка молча
  шла к следующей модели: перевод слова тратил запрос на отказ, у обычных
  задач не было последнего рубежа. У Google к 28.09 из списка пропали
  `gemini-2.0-flash-lite` и `gemini-3-pro-preview`. Замена — на прямых
  наследников (`openai/gpt-oss-20b` / `-120b`, `2.5-flash-lite`,
  `3.1-pro-preview`). Сверять перед выкаткой новых цепочек —
  `check-ai-models.mjs`.

**dev = прод**

- В разработке `/api/gemini` и `/api/transcribe` отвечают ТЕ ЖЕ обработчики:
  `vite.config.ts` зовёт их через адаптер (`vercelRoute`), Vercel CLI не
  нужен. Раз код тот же, то вход, права и энергия тоже: **`npm run dev`
  списывает на ЖИВОЙ базе**, `npm run dev:test` — на тестовой.
- Ключи в `.env.local` — **без** префикса `VITE_`, иначе уедут в браузер.

**Сборка Vercel строже нашей**

- `npm run build` не видит того, на чём падает Vercel: мы проверяем `api/` по
  `tsconfig.node.json` со `strict: true`, а Vercel читает КОРНЕВОЙ
  `tsconfig.json`. Пока в нём не было `compilerOptions`, функции
  компилировались со `strictNullChecks: false`, а в этом режиме TypeScript не
  сужает размеченные объединения: `if (!access.ok) return
  res.status(access.status)` падало с «Property 'status' does not exist on
  type AuthResult» — на Vercel и только там. Лечится явным предикатом
  (`authDenied` в `_auth.ts`), а не приведением типа. В корневом tsconfig
  теперь строгие настройки, и `check-api-vercel.mjs` проверяет `api/` в самом
  слабом режиме — оба конца закрыты.
- Из клиентского кода `api/` берёт только `src/shared/api/aiTypes.ts` —
  правило и почему: `src/shared/CLAUDE.md`.

## Как проверить

- `node scripts/test-aitasks.mjs` (чистый, в CI) — тип и карта задач в обе
  стороны, каждую задачу шлёт экран.
- `node scripts/test-ai-timeouts.mjs` (чистый, в CI) — зависание каждого
  поставщика, бюджет, поток, обычное поведение при 429/503.
- `node scripts/check-api-vercel.mjs` (в CI) — `api/` так, как их собирает
  Vercel.
- `node scripts/check-ai-models.mjs [--call]` — каждая модель цепочек есть у
  поставщика (список моделей квоту не тратит; `--call` — запросом к Groq).
- `node scripts/smoke-ai-dev.mjs [--call] [--expect-cheap]` — dev отказывает
  ученику в учительской задаче, как прод.
- `node scripts/check-ai-gateway.mjs` — настоящие обработчики и тестовая база,
  модели поддельные: списание → журнал → возврат.
- `node scripts/check-ai-quota-path.mjs --prod` — каким путём шли списания
  на живой базе (только чтение).

## Решения и почему

- **`consume_ai_quota` удалена** (Ф1.6) — первое поколение лимитов со своими
  цифрами: на живой базе за 40 дней все 187 списаний прошли через
  `spend_energy` (`check-ai-quota-path.mjs --prod`).
- **Ключа от базы у сервера нет** — корневой `CLAUDE.md`, «Безопасность»,
  правило 3 (отсюда возврат ⚡ по номеру списания). Исключение — `notify.ts`:
  его будит база, вход — секрет.
